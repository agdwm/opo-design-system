# opo-card

Primitive visual container del **Design System OPO**.

El componente está construido con `Stencil` y `Shadow DOM`. Está pensado como una superficie visual reutilizable para componer distintos tipos de cards sin imponer una estructura interna concreta.

`opo-card` aporta:

- superficie,
- borde,
- sombra,
- radio,
- padding interno,
- ancho opcional full-width,
- affordance visual interactiva opcional,
- y raíz semántica configurable.

La estructura interna del contenido pertenece al consumidor.

---

## Import

```tsx
import "@opo/components/opo-card";
```

---

## Basic usage

```html
<opo-card>
  <h3>Plan semanal</h3>
  <p>Organiza sesiones de estudio y repasos.</p>
</opo-card>
```

---

## Composition-first

`opo-card` no define slots específicos para `header`, `media`, `content`, `footer` o `actions`.

Esto permite construir diferentes composiciones sobre la misma primitive visual:

```html
<opo-card as="article">
  <div class="study-card">
    <span class="study-card__eyebrow">Preparación</span>
    <h3 class="study-card__title">Plan semanal</h3>
    <p class="study-card__description">Organiza tus sesiones de estudio, repasos y simulacros.</p>
    <opo-button>Ver plan</opo-button>
  </div>
</opo-card>
```

---

## Variants

```html
<opo-card variant="default">...</opo-card>
<opo-card variant="outlined">...</opo-card>
<opo-card variant="elevated">...</opo-card>
```

### Default

Card base con shadow suave.

### Outlined

Card con borde y sin elevación.

### Elevated

Card con shadow más pronunciada para destacar jerarquía visual.

---

## Sizes

La prop `size` controla:

- padding interno,
- radio,
- y densidad visual general.

```html
<opo-card size="sm">...</opo-card>
<opo-card size="md">...</opo-card>
<opo-card size="lg">...</opo-card>
```

---

## Semantic root element

La prop `as` permite controlar el elemento semántico raíz renderizado por la card.

```html
<opo-card as="div">...</opo-card>
<opo-card as="article">...</opo-card>
<opo-card as="section">...</opo-card>
```

Por defecto:

```html
<div></div>
```

Usa:

- `article` cuando la card representa una pieza de contenido independiente;
- `section` cuando agrupa una sección temática dentro de una página;
- `div` cuando solo es una superficie visual sin significado semántico propio.

---

## Interactive

`interactive` añade affordance visual interactiva, pero no convierte la card en un control interactivo.

```html
<opo-card interactive>...</opo-card>
```

El componente:

- no añade semántica de botón,
- no añade navegación,
- y no emite eventos especiales.

Para navegación o acciones, compón el contenido con:

- `opo-link`,
- o `opo-button`.

---

## Full width

```html
<opo-card full-width>...</opo-card>
```

Hace que la card ocupe todo el ancho disponible del contenedor.

---

## Custom properties

`opo-card` expone custom properties internas para adaptar su superficie visual cuando sea necesario:

```css
opo-card {
  --opo-card-padding-block: var(--sys-space-lg);
  --opo-card-padding-inline: var(--sys-space-xl);
  --opo-card-background: var(--sys-color-surface-panel);
  --opo-card-border-color: transparent;
  --opo-card-shadow: var(--ref-shadow-sm);
  --opo-card-radius: var(--ref-radius-sm);
}
```

Úsalas para ajustes contextuales de composición. Si una decisión visual se reutiliza en varios contextos, considera elevarla a un token del sistema.

---

## Accessibility

`opo-card` no introduce semántica interactiva por sí mismo.

Buenas prácticas:

- usa `as="article"` para contenido independiente;
- usa `as="section"` cuando agrupe contenido temático;
- no uses `interactive` como sustituto de un enlace o botón real;
- si toda la card debe navegar, compón internamente un `opo-link` o estructura la interacción de forma accesible;
- mantén una jerarquía de headings coherente con la página.

---

## Design System rationale

Esta implementación sigue una estrategia de primitive composable:

```txt
opo-card
→ wrapper visual reusable
→ sin estructura interna obligatoria
→ composición libre por contexto
```

Esto evita acoplar la card a un único patrón de producto y permite construir encima composiciones específicas como feature cards, stat cards, promo cards o course cards.

---

## Implementation notes

- `opo-card` está diseñado intencionadamente como un primitivo visual y no como un patrón de contenido rígido.
- La estructura interna pertenece al consumidor, por lo que el componente no expone slots de `header`, `content`, `footer` o `actions`.
- La prop `interactive` únicamente añade una affordance visual. No añade semántica de enlace o botón, ni atributos como `role` o `tabindex`.
- Utiliza la prop `as` para seleccionar el elemento semántico más adecuado según el contexto.
- Los estados hover solo se aplican en dispositivos que soportan hover mediante un puntero preciso.
- El componente respeta `prefers-reduced-motion` cuando el usuario ha solicitado reducir animaciones.
